# 口播一条龙

总调度：只管顺序、交接和卡点，具体做法在各步的 skill 里。
博主只做四件事：确认稿子、录口播、看预览、定标题。其余都由你完成；博主不录屏、不手动剪辑。
目标节奏：稿子定稿到长版出片 ≤ 2 小时。账号设定（名字、定位、配色、目录）读 [references/account.md](references/account.md)。

## 开工前（每期一次）

1. 问清这期是**竖屏**（小红书/视频号/抖音，1080×1920）还是**横屏**（B 站/小红书，1920×1080）。没说就按竖屏。横屏只是各 skill 里“横屏”一节的数值不同，通用规则不变。
2. 运行 `python3 scripts/check_env.py`（路径相对本文件所在目录；它用 `scripts/fontkit.py` 查字体）。缺 ffmpeg/Pillow 按提示装；缺字体运行 `bash scripts/get_fonts.sh`。
3. 本期文件夹 `~/projects/口播/<MMDD 选题>/` 不存在就建，下设 `成片/ 图解/ 网页演示/ 粗剪/ 脚本/`。

## 流程

| 步 | 做什么 | 用哪个 skill | 产出（交接文件） | 谁动手 |
|---|---|---|---|---|
| 0 | 选题自检 | koubo-baokuan-check（选题模式） | 结论：做 / 换角度 | 你 |
| 1 | 选题 → 逐字稿 | koubo-script | `脚本/逐字稿.md`，含【图解N】【素材N】和来源 | 你 |
| 1.5 | 稿件自检 | koubo-baokuan-check（稿件模式） | 自检报告，必须改的改完 | 你 |
| ✋ | 确认稿子 | — | 定稿 | 博主 |
| 2A | 白板图解 | whiteboard-diagram | `图解/图解N.mp4` | 你（与录制并行） |
| 2B | 真实网页演示 | web-page-demo | `网页演示/素材N.mp4` | 你（与录制并行） |
| ✋ | 录口播，导出视频和 SRT | — | 原始视频 + `.srt` | 博主 |
| 3 | 粗剪 → 合成 → 声音 | koubo-edit-pipeline（内部用 koubo-subtitle-fx） | `project.json`、预览、长版、短版 | 你 |
| ✋ | 看预览 | — | 修改意见或通过 | 博主 |
| 4 | 标题 + 封面 | koubo-cover | 标题候选、封面 | 你出，博主定 |
| 5 | 交付 | — | 放进本期文件夹各子目录 | 你 |
| 6 | 发布 3 天后复盘 | koubo-baokuan-check（复盘模式） | 写进 `复盘/` | 博主给数据，你写 |

## 执行规则

1. **按顺序走，不跳步。** 第 0 步结论是“换角度”就停下来改写选题，不往下写稿。
2. **自检是硬卡点。** 第 1.5 步“必须改”没改完，不把稿子交给博主确认。录完再改就要补录。
3. **第 2 步和录制并行。** 稿子一定稿就开始做图解和网页演示。
4. **每个 ✋ 都停下来等。** 说清需要博主做什么、给什么文件，不替她做决定。
5. **先出预览再出成片。** 预览通过后才渲染长版；短版在长版之后。
6. **每步开头说一句**现在在第几步、预计多久。

## 某个 skill 不可用时

先看这一步要用的 skill 在不在。不在就明说，然后按 [references/specs.md](references/specs.md) 的规格先做，不要另起一套风格。
ra-hook、ra-renhua 是可选搭档：没有就按 koubo-script / koubo-edit-pipeline 里写明的备用做法。

## 文件放哪

- 所有项目在 `~/projects/口播/`，每期一个文件夹 `MMDD 选题`。可复用的脚本在各 skill 自己的 `scripts/` 里。
- **不要放桌面或“文稿”**：这两个位置会同步 iCloud，大视频会一直上传。
- 上一期成品是风格参照：上一期的成品文件夹（`~/projects/口播/<上一期>/`）。

## 长任务（在 VS Code 里）

终端工具对长命令会超时。渲染类命令（长版等）用 `nohup <命令> > 渲染.log 2>&1 &` 放后台，再用 `tail -n 5 渲染.log` 查进度，并提前告诉博主要等多久。大视频一律分段处理，别整条读进内存。

## 检查这套 skill 本身

改过任何 skill 之后运行 `python3 scripts/check_skills.py`：检查 frontmatter、名字和目录一致、正文大小、脚本语法、写死的路径、引用的文件是否存在。有 ❌ 的必须修。规格依据见 [README.md](README.md)。

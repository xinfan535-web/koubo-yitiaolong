# 口播剪辑流水线

口播一条龙的第 3 步。博主只负责录和导出，其余全部在这里完成，她不手动剪辑。
数值（圆窗、字幕位置）按画幅分，对照表见同一 skills 目录下的 koubo-yitiaolong/references/specs.md；`project.json` 的字段在 [references/project-json.md](references/project-json.md)。

**现状**：粗剪、合成、混音的脚本还没有沉淀（之前只留下成品），要按下面规格现写。第一次写完并跑通后存进本 skill 的 `scripts/` 并在这里补用法。**横屏只定了规格，没在真实横拍素材上跑过**，第一期横屏要多留时间。

## 输入

在 `~/projects/口播/<MMDD 选题>/` 下：`粗剪/` 里博主导出的口播视频（通常已美颜）和剪映导出的 `.srt`；补录片段（短版钩子）及其 `.srt`；`图解/图解N.mp4`、`网页演示/N ….mp4`；定稿逐字稿（含【图解N】【素材N】和章节名）。缺哪样直接说缺什么，不猜。

## 一个 project.json 驱动全流程

所有决定写进 `<本期文件夹>/project.json`，渲染只读它。改片子 = 改这个文件再重渲，不手改中间产物。时间点尽量用字幕序号表达，粗剪改动后不用重算秒数。字段见 references/project-json.md。画幅用 `"orient": "landscape"` 区分，不写就是竖屏。

## 步骤

**1. 选句粗剪**
- 读 SRT 对照逐字稿逐句标：保留 / 删除。删口误、重说（保留最后一遍完整的）、插话、和正文无关的话。
- 句间停顿压到约 0.25 秒，句首句尾各留一点气口，不要剪到字。剪点落在静音处：SRT 时间只作参考，用静音检测微调到最近的静音点。
- 拿不准删不删的句子列出来问用户，不替她删观点。
- **逐段剪再拼接，不要一次把整条读进内存**（爆过内存）。

**2. 镜头和圆窗**
- 默认人物全屏。讲到【图解N】或【素材N】那几句：素材全屏，人缩进圆窗，圆里裁人脸和肩膀、脸居中，白边加柔和阴影。
- 圆窗：竖屏圆心约 (880,1385)、直径约 310、白边约 6；横屏圆心 (1700,860)、半径 150。
- 素材比她讲的短：冻结在最后一帧；比她讲的长：截断，不加速。切入切出用硬切或极短过渡，不用花哨转场。

**3. 字幕**
调用 koubo-subtitle-fx（它负责判断金句、分点、清单、关键词并配样式）。这里保证：字幕时间轴用**粗剪之后的新时间**，不是原始 SRT 的；普通字幕位置和字数按画幅（竖屏中心约 68% 高度、≤14 字；横屏黑条中心 y≈1010、≤20 字）；SRT 错字按逐字稿改正。

**4. 声音**
- 人声统一到 **−16 LUFS**，真峰值 ≤ −1 dBTP。补录片段单独测响度再对齐正片。
- 背景音乐：轻的 lo-fi，原创或确认可商用；说话时自动压低（sidechain ducking），“有氛围但不抢话”。音效全片约 5 个，只放在切图解、出金句、章节切换处。
- **混音后检查总时长和最后 3 秒**：混音吞过结尾，以人声轨长度为准。

**5. 画质**：轻锐化（unsharp 小强度），不磨皮不调脸。输出 30fps、h264；竖屏 1080×1920、横屏 1920×1080；长版码率约 9 Mbps，短版约 12 Mbps；音频 AAC。

**6. 出片顺序**
1. **预览**：低码率，整条能看。发给用户，说明删了哪些句子、哪几处拿不准，**停下来等她**。
2. **长版**：通过后高码率渲染。
3. **短版**（约 1.5 分钟）：补录钩子 + 逐字稿指定的正片片段，结尾接身份钩子。

## 交付前自查

总时长和预期一致、结尾没被截；响度实测在 −16 LUFS 上下 1 以内；抽 6–8 帧看字幕不出框不挡脸、圆窗位置正确；抽开头、中间、结尾各听一段确认声画同步。

## 交付位置

```
~/projects/口播/<MMDD 选题>/
  成片/（完整版-<名>.mp4、短版-<名>.mp4、封面）  图解/  网页演示/  粗剪/  脚本/  project.json
```

改版文件名加 v2、v3，不覆盖博主看过的版本。中间文件放名字带“（可删除）”的文件夹。成品参照：上一期 `成片/` 里的完整版和短版，做新一期前抽几帧对照。

# 口播剪辑流水线

口播一条龙的第 3 步。博主只负责录和导出，其余全部在这里完成，她不手动剪辑。
数值（人物角标、字幕位置、进度条）按画幅分，对照表见同一 skills 目录下的 koubo-yitiaolong/references/specs.md；进度条细节在 [references/progress-bar.md](references/progress-bar.md)；`project.json` 的字段在 [references/project-json.md](references/project-json.md)。

**现状**：粗剪、合成、混音的脚本还没有沉淀（目前只留下成品），要按下面规格现写。第一次写完并跑通后存进本 skill 的 `scripts/` 并在这里补用法。横屏已实测跑通（当时交付为 4:3）；做 16:9 时裁切和字幕位置需重新核对。

## 输入

在 `~/projects/口播/<MMDD 选题>/` 下：`粗剪/` 里博主导出的口播视频（通常已美颜）和剪映导出的 `.srt`；补录片段（短版钩子）及其 `.srt`；`图解/图解N.mp4`、`网页演示/N ….mp4`；定稿逐字稿（含【图解N】【素材N】和章节名）。缺哪样直接说缺什么，不猜。

## 一个 project.json 驱动全流程

所有决定写进 `<本期文件夹>/project.json`，渲染只读它。改片子 = 改这个文件再重渲，不手改中间产物。时间点尽量用字幕序号表达，粗剪改动后不用重算秒数。字段见 references/project-json.md。画幅用 `"orient": "landscape"` 区分，不写就是竖屏。

## 步骤

**1. 选句粗剪**
- 读 SRT 对照逐字稿逐句标：保留 / 删除。删口误、重说（保留最后一遍完整的）、插话、和正文无关的话。
- 句间停顿压到约 0.25 秒，句首句尾各留一点气口，不要剪到字。剪点落在静音处：SRT 时间只作参考，用静音检测微调到最近的静音点。
- 拿不准删不删的句子列出来问用户，不替她删观点。
- **逐段剪再拼接，不要一次把整条读进内存**（爆过内存）。

**2. 画幅与录屏呈现方式**
项目开始时问一次，写进 project.json，不自动判断：
- 画幅（`orient`）：竖屏（默认）或横屏。
- 录屏/图解/网页素材怎么呈现（新增字段 `screen_mode`）：
  - `"split"`（上下操作风格）：人物固定在上半屏，录屏/演示固定在下半屏，全程同时露出，不做切入切出；片头片尾人物切回全屏，全屏和分屏之间用叠化过渡，不是硬切。
  - `"interactive"`（交互式操作风格，原来的默认做法）：没点名要分屏呈现的句子人物全屏；讲到【图解N】【素材N】或录屏操作那几句，素材全屏、人物缩进角标。再选一次角标位置（新增字段 `pip_position`）：`"bottom_left"`（默认）或 `"bottom_right"`。
- 这两种只影响**需要全屏呈现素材**的句子；纯讲解的句子始终人物全屏，和画幅、录屏模式无关。

`interactive` 模式下，素材切入的那一刻怎么处理（新增字段 `insert_style`，**测试中，可调用**）：
- `"static"`（默认，现状）：素材切入切出用硬切或极短过渡，人物缩进角标是直接到位，没有额外动效。
- `"wanggan"`（网感剪辑，测试中）：**片头开场**先给人物全屏，再用一个快速推镜/缩小的动画把人收进角标，配开场音效；之后每次素材切入同样用推镜/缩小过渡，配短促转场音效（click/whoosh 类）；讲到金句可以推镜放大强调，这时不出字幕。

`interactive` 模式的角标规格：
- 形状是圆角矩形（不是圆），裁切比脸部特写更宽，露出胸肩，头顶留一点空间，不要贴边显得压迫。
- 角标位置：竖屏中心 y≈1385，左下 x≈200 / 右下 x≈880；横屏中心 y≈860，左下 x≈220 / 右下 x≈1700。
- 角标大小随内容变化，带缩放推镜的过渡动画（有剪辑动画感，不是瞬间跳变）：网页演示/被动展示类片段角标偏小；讲到点击、操作强调的瞬间（点一下鼠标、点开某个选项）角标偏大。
- 素材比她讲的短：冻结在最后一帧；比她讲的长：截断，不加速。切入切出的过渡按 `insert_style`：`static` 用硬切或极短过渡，不用花哨转场；`wanggan` 按上面的网感过渡处理。

**3. 字幕**
调用 koubo-subtitle-fx（它负责判断金句、分点、清单、关键词并配样式）。这里保证：字幕时间轴用**粗剪之后的新时间**，不是原始 SRT 的；普通字幕位置和字数按画幅（竖屏中心约 68% 高度、≤14 字；横屏黑条中心 y≈1010、≤20 字）；SRT 错字按逐字稿改正。样式按 koubo-subtitle-fx 的「当前定版」（白字 + 淡黄底条、关键词亮黄；标题在白字灰影和红条里选，加标题时先问博主；同一时刻只出一种字）；片头片尾加人物介绍。

**4. 声音**
- 人声统一到 **−16 LUFS**，真峰值 ≤ −1 dBTP。补录片段单独测响度再对齐正片。
- 背景音乐：固定用博主选定的一首轻音乐，每期不换（见 account.md）；还没定曲子就交付不带 BGM 的版本并说明。有 BGM 时说话自动压低（sidechain ducking），"有氛围但不抢话"。
- 音效：**剪辑动效都要配音效**（推镜/缩放、角标变大变小、切素材、网感转场），不出现没声音的动效；强调音效（出金句、章节切换）另算，全片约 5 个；片头第一句配开场音效。
- 音效都在博主电脑上的音效库 `~/projects/口播/000-给agent的参考/_素材库/音效/`。**混音前先读里面的 `音效库.json`**：每个音效的文件、用在哪、默认音量（gain_db）、放在哪句话都写在表里，照表放；表里没有的用途才用 `通用-合成备用/` 里的合成音效，并在标注表里注明。网感转场音效的对应：click → 切网页演示，swish → 切白板图解，whoosh → 快速推镜，pop → 跳切放大，ding → 章节开头。新音效放进对应文件夹，并在 `音效库.json` 里加一条。
- **找不到音效库，或表里写的文件不存在，就停下来问博主**，给两个办法让她选：① 让 agent 先合成一套基础音效（click、swish、whoosh、pop、ding）；② 去剪映音效库下载。放进音效库后在 `音效库.json` 登记再用，不擅自从网上下载。在 Claude 里剪辑时，要先把音效库文件夹连接进来。
- 上下分屏：录屏里每次点击/切换配短促 click、toggle 音效（录屏没收声就用合成音效），音量压低。
- **混音后检查总时长和最后 3 秒**：混音吞过结尾，以人声轨长度为准。

**5. 画质**：轻锐化（unsharp 小强度），不磨皮不调脸。输出 30fps、h264；竖屏 1080×1920、横屏 1920×1080；长版码率约 9 Mbps，短版约 12 Mbps；音频 AAC。

**6. 进度条（只加在竖屏长版）**：规范和渲染方法见 references/progress-bar.md。没装 video-progress-studio 就先出不带进度条的长版，并告诉用户。渲染很慢，按那份文档的方法分段，并提前告知等待时间。

**7. 出片顺序**
1. **预览**：低码率、无进度条，整条能看。发给用户，说明删了哪些句子、哪几处拿不准，**停下来等她**。
2. **长版**：通过后高码率渲染，竖屏叠进度条。
3. **短版**（约 1.5 分钟）：补录钩子 + 逐字稿指定的正片片段，结尾接身份钩子，不加进度条。

## 交付前自查

总时长和预期一致、结尾没被截；响度实测在 −16 LUFS 上下 1 以内；抽 6–8 帧看字幕不出框不挡脸、角标位置正确、进度条章节对得上内容；抽开头、中间、结尾各听一段确认声画同步。
